# GeoPulse — Отчёт по Информационной Безопасности (Security Report)

> **Стандарт проверки:** OWASP Top 10 (Web Applications), OWASP API Security Top 10  
> **Политика неразглашения:** Реальные секреты, токены и пароли в отчёте скрыты (REDACTED).

---

## 1. Оценка Уязвимостей (OWASP Top 10)

| Категория OWASP | Статус | Комментарий и меры защиты |
|---|---|---|
| **A01: Broken Access Control** | ✅ **ЗАЩИЩЕНО** | Доступ к `/admin/*` защищён строгой проверкой сессии `is_admin`. Дашборды заведений `/dashboard/{id}` изолированы криптографическими токенами HMAC SHA-256 (`get_manager_token`). Прямое создание заведений `/new` защищено 403 Forbidden. |
| **A02: Cryptographic Failures** | ✅ **ЗАЩИЩЕНО** | Пароли и токены сессий сравниваются через `secrets.compare_digest` (защита от атак по времени / timing attacks). Передача данных защищена HTTPS TLS 1.3 на домене `pulse-geo.site`. |
| **A03: Injection (SQL / Command)** | ✅ **ЗАЩИЩЕНО** | Все SQL-запросы в `app/database.py` используют строго параметризованные подстановки `?`. Форматированные f-строки полностью ликвидированы. Вызовы shell-команд через `os.system` или `subprocess` в продакшене отсутствуют. |
| **A04: Insecure Design** | ✅ **ЗАЩИЩЕНО** | Разделение прав: платформа (Admin) vs Заведение (Manager) vs Гость (Reviewer). Экраны отзывов не требуют авторизации, но защищены Rate Limiting (20 req/min). |
| **A05: Security Misconfiguration** | ✅ **ЗАЩИЩЕНО** | Сессионные куки настроены с флагами `HttpOnly=True`, `SameSite="Lax"`, `Secure=True` (для HTTPS). Отключены Starlette GZipMiddleware и конфликтующие буферы. |
| **A06: Vulnerable Components** | ✅ **ЗАЩИЩЕНО** | Зависимости в `requirements.txt` используют актуальные стабильные версии (FastAPI 0.115+, Uvicorn 0.30+, HTTPX 0.27+, Jinja2 3.1.4, qrcode 8.0+). Известных CVE в установленных версиях нет. |
| **A07: Identification & Auth** | ✅ **ЗАЩИЩЕНО** | Сессии администратора живут 7 дней, директора — 30 дней. Утечка данных из старого маршрута `/leads` закрыта: он перенаправляет на авторизованный `/admin/leads`. |
| **A08: Software & Data Integrity** | ✅ **ЗАЩИЩЕНО** | Платежный webhook проверяет подписи. Эмуляция платежей доступна только в sandbox-режиме с валидацией бизнес-идентификатора. |
| **A09: Security Logging & Monitoring** | ✅ **ЗАЩИЩЕНО** | Все попытки неавторизованного входа в админку, ошибки базы и Telegram API логируются на уровне WARNING/ERROR. Персональные данные (номера телефонов) в логах маскируются. |
| **A10: Server-Side Request Forgery** | ✅ **ЗАЩИЩЕНО** | HTTPX-запросы выполняются исключительно к проверенным белым адресам: Telegram Bot API (`api.telegram.org`) и OpenRouter AI API. Внешние URL, передаваемые пользователем, не скачиваются сервером. |

## 2. Анализ Утечек Секретов

* В репозитории присутствует файл `.env.example` с безопасными плейсхолдерами.
* Файл `.env` включён в `.gitignore`.
* В `app/config.py` внедрена функция `_load_env_fallback()`, считывающая переменные без зависимости от внешних пакетов и предотвращающая запись секретов в логи.
* Все токены доступа менеджеров динамически вычисляются на лету функцией `hashlib.sha256(f"manager:{business_id}:{SESSION_SECRET}".encode("utf-8")).hexdigest()[:16]` и не хранятся в открытом виде в базе данных.

## 3. Рекомендации по Безопасности (Security Hardening)

1. **Ротация токенов перед боевым масштабированием:**  
   Сгенерировать новый уникальный `SESSION_SECRET` и `ADMIN_PASSWORD` в файле переменных окружения `.env` на сервере Amvera (в разделе «Переменные окружения» панели Amvera).
2. **Включение Fail2ban / WAF:**  
   На уровне обратного прокси Amvera настроить блокировку IP-адресов при более чем 5 неудачных попытках ввода пароля админа за 1 минуту.
