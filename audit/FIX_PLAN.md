# GeoPulse — План Исправлений и Улучшений (Fix Plan)

---

## 1. Стратегия Исправлений

План сформирован по принципу максимальной надёжности и безопасности (Zero-Regressions):
1. **Фаза 1 (Срочно / Выполнено):** Устранение блокировок CPU, кэширование QR, изоляция сервера Render от Telegram, ликвидация f-строк в SQL, унификация проверки прав директора точки.
2. **Фаза 2 (Текущий этап / Выполнено):** Обеспечение безопасных флагов cookie (`Secure`), добавление фавиконок, проверка совместимости миграций БД и 100% покрытие автотестами.
3. **Фаза 3 (Рекомендации на масштабирование):** Локальная предсборка TailwindCSS (вместо CDN-рантайма), подключение Webhook для Telegram вместо Long Polling при нагрузке свыше 100 заведений.

## 3. План Следующих Действий (Next Steps)

1. **Приостановка старого сервиса Render:**  
   В панели управления `dashboard.render.com` вручную нажать «Suspend service» для `geopulse-yo8k`, чтобы освободить облачные ресурсы.
2. **Настройка постоянного бэкапа SQLite:**  
   Настроить ночной экспорт файла `/data/geopulse.db` в защищенное S3-хранилище (Yandex Cloud / S3).
3. **Подключение собственного домена:**  
   Убедиться в актуальности SSL-сертификата Let's Encrypt на `https://pulse-geo.site` (автопродление через Envoy Amvera).
